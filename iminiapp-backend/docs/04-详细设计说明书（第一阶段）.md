## 2. 首页聚合设计

首页由一个只读聚合接口提供，避免小程序分别请求轮播、公告和入口造成首屏阻塞。

### 2.1 数据读取规则

1. 轮播图仅返回 `enabled=true` 且当前时间处于展示区间的数据，按 `sort` 升序。
2. 快捷入口和特色服务仅返回启用项目；跳转目标必须是平台已注册的小程序页面或已发布资源。
3. 公告优先返回置顶且已发布的一条；无数据时前端隐藏公告条。
4. 公共配置中的客服电话可以匿名读取；反馈提交需登录并执行频率限制。

### 2.2 缓存策略

首页聚合响应可缓存 5 分钟。管理端修改轮播、公告、入口或平台配置后，后端应删除对应缓存键。缓存仅优化读取，不作为数据真相来源。

## 3. 订单与库存详细规则

### 3.1 创建订单

1. 校验用户状态、资源状态、SKU 状态和日期/时段规则。
2. 在一个数据库事务中，以条件更新扣减库存：`available_quantity >= requested_quantity` 是成功条件。
3. 扣减成功后创建订单及明细快照，生成全局唯一订单号，状态为 `PENDING_PAYMENT`。
4. 设置支付超时。超时任务仅能把仍处于 `PENDING_PAYMENT` 的订单改为 `CANCELLED`，并归还库存。

### 3.2 支付回调

1. 校验微信支付签名、商户号、金额及订单号；不得相信客户端传入的支付结果。
2. 根据支付渠道流水号做唯一约束，重复回调直接返回成功，不重复记账。
3. 只有 `PENDING_PAYMENT` 状态的订单可迁移为 `PAID`；写入支付流水和审计日志。

### 3.3 核销

1. 电子核销码仅保存 SHA-256 摘要，明文码不写入数据库日志。
2. 核销前校验订单已支付、服务日期/有效期、资源可使用状态及核销码未使用。
3. 以条件更新将状态从 `UNUSED` 改为 `USED`，并记录操作员、时间、设备/渠道；重复扫描返回“已核销”。

## 4. 错误码与审计

统一响应格式：`code`、`message`、`data`、`traceId`。错误码按域划分，例如 `AUTH_401`、`RESOURCE_404`、`INVENTORY_409`、`ORDER_409`、`PAYMENT_422`。

用户资料、权限变更、价格/库存修改、退款、核销和系统参数变更必须写入 `bf_audit_log`。审计日志只追加、不允许业务接口修改。

## 5. 尚待确认的详细设计输入

- 房型、会议室、餐桌、车辆、票种、场馆和商品的字段及价格/退改规则。
- 会议/内部用车审批节点、候选审批人和超时处理方式。
- 微信支付、短信、门禁、地图、OA/财务系统的真实接口参数与安全要求。

这些输入确认后，应为每一个业务模块补充页面流程、状态机、字段字典、接口和测试用例。
