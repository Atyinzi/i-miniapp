# 测试方案与报告边界

## 当前可完成

| 文档 | 当前可交付内容 | 不能在当前阶段声称的内容 |
| --- | --- | --- |
| 系统测试报告 | 测试范围、用例目录、环境和准入标准 | 通过率、缺陷数、实际执行结论 |
| 压力测试报告 | 场景、指标、数据准备和工具计划 | 吞吐量、P95、资源利用率等实测结果 |
| 安全测试报告 | 检查清单、工具与整改流程 | 漏洞扫描/渗透测试结果和“无漏洞”结论 |

## 功能测试首批用例

1. 首页：轮播排序、禁用内容不展示、公告点击、搜索空值与关键词。
2. 资源：下架资源不可下单、SKU 价格/库存展示正确。
3. 订单：重复提交幂等、库存不足、超时取消归还库存、取消/退款状态限制。
4. 支付：签名错误拒绝、重复回调不重复记账、金额不一致拒绝。
5. 核销：有效码成功、重复码拒绝、过期码拒绝、无权限操作拒绝。
6. 权限：普通用户不能访问管理接口，管理员操作产生审计日志。

## 压力测试计划

- 工具：JMeter、k6 或同等工具；实际工具及版本须写入报告。
- 场景：首页读取、资源查询、创建订单、支付回调、核销。
- 指标：接口成功率、P50/P95/P99、吞吐量、错误率、MySQL/Redis/应用 CPU 和内存。
- 判定：以需求的单接口 ≤500ms、复杂查询 ≤1s、支持 ≥1000 同时在线为目标；报告必须写明数据规模、机器配置、持续时间和瓶颈，不得只给结论。

## 安全测试计划

- 认证与授权、越权、会话有效期、敏感数据脱敏、日志泄露。
- SQL 注入、XSS、文件上传、接口限流、重放与支付回调验签。
- 依赖漏洞扫描、配置检查、数据库备份恢复演练。

测试报告的实际结果必须在可部署环境中执行后生成，并附执行日期、环境、原始数据/截图、缺陷编号及复测结论。
