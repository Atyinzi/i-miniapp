# 文创商城商品与库存模块说明

## 1. 当前完成范围

本阶段完成文创商城后端第一、二阶段：

1. 文创商品分类新增、编辑、排序和启停。
2. 商品 SPU、SKU、图片、富文本详情、价格、重量和上下架管理。
3. 用户端已上架商品分类、列表、关键词搜索和详情查询。
4. SKU 实际库存、锁定库存、可售库存和低库存阈值。
5. 单 SKU 入库、出库、退货入库、报损和盘点调整。
6. 最多 200 条的批量入库/出库，任一失败时整批回滚。
7. 库存幂等、防负库存、库存流水、操作审计和低库存预警查询。

优惠、真实支付、物流和售后属于后续阶段。收货地址、购物车与文创订单已在第三阶段补齐。

## 2. 管理端接口

统一前缀：`/api/v1/admin/cultural-store`。

| 功能 | 方法 | 地址 |
|---|---|---|
| 分类列表/新增 | GET / POST | `/categories` |
| 编辑分类 | PUT | `/categories/{categoryId}` |
| 商品分页/新增 | GET / POST | `/products` |
| 商品详情/编辑 | GET / PUT | `/products/{productId}` |
| 商品上下架 | PATCH | `/products/{productId}/status` |
| 新增 SKU | POST | `/products/{productId}/skus` |
| 编辑 SKU | PUT | `/skus/{skuId}` |
| 库存及预警 | GET | `/stocks?lowStock=true` |
| 单 SKU 库存调整 | POST | `/stocks/{skuId}/adjustments` |
| 批量库存调整 | POST | `/stocks/batch-adjustments` |
| 库存流水 | GET | `/stock-logs?skuId={skuId}` |

所有库存写接口必须携带唯一的 `Idempotency-Key`。批量接口为每个明细派生独立幂等键，整批事务提交或回滚。

库存变更类型：`INBOUND`、`OUTBOUND`、`ADJUSTMENT`、`RETURN`、`DAMAGE`。入库和退货数量为正数，出库和报损数量为负数，盘点调整可正可负。

## 3. 用户端接口

统一前缀：`/api/v1/app/cultural-store`。

| 功能 | 方法 | 地址 |
|---|---|---|
| 可用分类 | GET | `/categories` |
| 商品列表与搜索 | GET | `/products?keyword=i某小程序&categoryId=1&page=1&pageSize=20` |
| 商品详情 | GET | `/products/{productId}` |

用户端只返回已上架商品、启用分类和启用 SKU，不公开库存流水及后台状态数据。

## 4. 数据边界

- `bf_resource`、`bf_resource_sku` 和 `bf_resource_image` 继续作为统一商品基础模型。
- `bf_cultural_product_profile` 保存文创 SPU 专属资料。
- `bf_cultural_stock` 是实体库存，不使用按日期/时段设计的 `bf_inventory`。
- `on_hand_quantity = locked_quantity + available_quantity` 由数据库约束保护。
- 后续订单阶段锁库时只移动“可售→锁定”，不会立即减少实际库存；支付或发货节点再按交易规则正式扣减。

## 5. 第三阶段：地址、购物车与订单

用户端继续使用 `/api/v1/app/cultural-store` 前缀：

| 功能 | 方法 | 地址 |
|---|---|---|
| 地址列表/新增 | GET / POST | `/addresses` |
| 编辑/删除本人地址 | PUT / DELETE | `/addresses/{addressId}` |
| 购物车 | GET | `/cart` |
| 新增或修改购物车商品 | PUT | `/cart/items` |
| 选中/取消选中 | PATCH | `/cart/items/{skuId}/selection` |
| 删除购物车商品 | DELETE | `/cart/items/{skuId}` |
| 购物车结算或立即购买 | POST | `/checkout` |
| 文创订单详情 | GET | `/orders/{orderId}` |
| 取消待支付订单 | POST | `/orders/{orderId}/cancel` |

结算接口必须携带唯一 `Idempotency-Key`。`items` 为空时结算购物车中已选商品；传入 `items` 时按立即购买处理。收货地址在订单创建时复制为快照，用户后续修改地址不会改变历史订单。

待支付订单创建时将库存从“可售”移动到“锁定”；取消或15分钟未支付会原子释放。开发环境模拟支付成功后，锁定库存转为正式销售扣减。真实微信支付仍在后续支付阶段接入。

## 6. 第四阶段：满减、折扣与优惠券

后台接口继续使用 `/api/v1/admin/cultural-store` 前缀：

| 功能 | 方法 | 地址 |
|---|---|---|
| 活动列表/新增 | GET / POST | `/promotions` |
| 编辑活动 | PUT | `/promotions/{promotionId}` |
| 优惠券模板列表/新增 | GET / POST | `/coupons` |
| 编辑未发放模板 | PUT | `/coupons/{couponId}` |
| 向指定用户发券 | POST | `/coupons/{couponId}/issues` |

用户端接口：

| 功能 | 方法 | 地址 |
|---|---|---|
| 可领取优惠券 | GET | `/api/v1/app/cultural-store/coupons/claimable` |
| 领取优惠券 | POST | `/api/v1/app/cultural-store/coupons/{couponId}/claim` |
| 我的优惠券 | GET | `/api/v1/app/cultural-store/coupons/mine` |
| 订单金额试算 | POST | `/api/v1/app/cultural-store/pricing/quote` |

满减和折扣均支持 `ALL`、`CATEGORY`、`PRODUCT`、`SKU` 四级适用范围。系统在所有有效自动活动中选择优惠金额最大的一项；金额相同则选择优先级更高的活动。优惠券只有在 `stackable=true` 且自动活动不排他时才能叠加，否则明确拒绝使用。

前端试算仅用于展示。提交 `/checkout` 时可传 `userCouponId`，后端会基于订单商品价格快照重新计算、锁定用户券并更新 `discount_amount_cent` 和 `payable_amount_cent`。优惠结果写入 `bf_cultural_order_discount`，后续修改活动不影响历史订单。

为兼容当前支付链路，优惠后至少保留1分钱应付金额。取消或支付超时会释放用户券并回退优惠券使用次数；过期券自动转为 `EXPIRED`。已发放的优惠券模板禁止修改经济规则，应停用旧模板并新建。

## 7. 第六阶段：后台发货与物流跟踪

本阶段暂不接入真实微信支付，以订单已进入 `PAID` 状态为发货起点。后台接口继续使用 `/api/v1/admin/cultural-store` 前缀：

| 功能 | 方法 | 地址 |
|---|---|---|
| 物流公司列表/新增 | GET / POST | `/carriers` |
| 编辑物流公司 | PUT | `/carriers/{carrierId}` |
| 文创订单工作台 | GET | `/fulfillment/orders` |
| 文创订单履约详情 | GET | `/fulfillment/orders/{orderId}` |
| 订单备货 | POST | `/fulfillment/orders/{orderId}/prepare` |
| 单笔发货 | POST | `/fulfillment/orders/{orderId}/ship` |
| 批量发货 | POST | `/fulfillment/orders/batch-ship` |
| 修改物流单号 | PUT | `/fulfillment/orders/{orderId}/shipment` |
| 追加物流轨迹 | POST | `/fulfillment/orders/{orderId}/tracking-events` |
| 执行逾期自动收货 | POST | `/fulfillment/auto-receive-overdue` |

用户端新增接口：

| 功能 | 方法 | 地址 |
|---|---|---|
| 可用物流公司 | GET | `/api/v1/app/cultural-store/carriers` |
| 查看本人订单物流 | GET | `/api/v1/app/cultural-store/orders/{orderId}/shipment` |
| 确认收货 | POST | `/api/v1/app/cultural-store/orders/{orderId}/confirm-receipt` |

订单主状态按 `PAID → PREPARING → SHIPPED → COMPLETED` 流转。物流单内部支持 `PENDING`、`SHIPPED`、`IN_TRANSIT`、`EXCEPTION`、`DELIVERED`，物流异常会阻止自动收货；异常恢复并追加正常在途轨迹后可重新进入自动收货范围。默认在发货10天后自动确认收货，也支持用户主动确认。

备货、发货、批量发货、修改运单、追加轨迹、确认收货和手工触发自动收货均记录履约操作日志；写操作通过 `Idempotency-Key` 防止重复提交。当前边界为“一张文创订单对应一个物流单”，暂不支持拆单、多包裹和部分发货。

## 8. 第七阶段：退款与售后处理

用户端接口统一使用 `/api/v1/app/cultural-store` 前缀：

| 功能 | 方法 | 地址 |
|---|---|---|
| 提交售后申请 | POST | `/orders/{orderId}/after-sales` |
| 我的售后列表 | GET | `/after-sales` |
| 售后详情 | GET | `/after-sales/{id}` |
| 取消待审核申请 | POST | `/after-sales/{id}/cancel` |
| 填写退货物流 | POST | `/after-sales/{id}/return-shipment` |

后台接口统一使用 `/api/v1/admin/cultural-store/after-sales` 前缀：

| 功能 | 方法 | 地址 |
|---|---|---|
| 售后工作台 | GET | `/` |
| 售后详情 | GET | `/{id}` |
| 审核通过 | POST | `/{id}/approve` |
| 审核拒绝 | POST | `/{id}/reject` |
| 确认收到退货 | POST | `/{id}/receive-return` |
| 确认退款完成 | POST | `/{id}/complete-refund` |

`REFUND_ONLY` 适用于 `PAID`、`PREPARING` 的未发货订单，流程为 `PENDING_REVIEW → REFUNDING → COMPLETED`。`RETURN_REFUND` 适用于 `SHIPPED` 或确认收货不超过7天的 `COMPLETED` 订单，流程为 `PENDING_REVIEW → WAITING_RETURN → RETURNED → REFUNDING → COMPLETED`。待审核申请还可以进入 `REJECTED` 或 `CANCELLED`。

当前售后按整单处理，退款金额为订单实付金额，不支持部分商品或部分数量退款。退货退款在商家签收时回补文创实体库存；未发货仅退款在退款完成时回补库存，两种流程均使用库存流水防止重复入库。退款资金流水复用 `bf_refund`，由于真实微信支付尚未接入，当前由后台“确认退款完成”模拟渠道退款成功。

所有售后写操作必须携带唯一 `Idempotency-Key`。同一订单同一时间只能有一个进行中的售后单，操作过程记录售后状态日志、订单状态日志、审计日志和用户通知。

## 9. 第八阶段：销售与库存运营报表

后台报表统一使用 `/api/v1/admin/cultural-store/reports` 前缀：

| 功能 | 方法 | 地址 |
|---|---|---|
| 运营仪表盘聚合 | GET | `/dashboard?startDate=2026-08-01&endDate=2026-08-31` |
| 核心指标概览 | GET | `/overview` |
| 按日销售趋势 | GET | `/sales-trend` |
| 热销商品排行 | GET | `/top-products?limit=10` |
| 售后统计 | GET | `/after-sales` |
| 库存分析 | GET | `/inventory?lowStockOnly=true&page=1&pageSize=20` |
| 按日库存变动 | GET | `/stock-movements` |
| 销售明细CSV | GET | `/sales-export` |

除库存分析外，接口均接收 `startDate`、`endDate`，日期范围包含首尾两天且最长366天。销售额、订单数和销量以支付成功时间统计；退款金额以退款完成时间统计；净销售额为实付销售额减退款金额。待发货、进行中售后、低库存SKU、库存数量和库存货值为查询时的实时快照，不受日期范围限制。

销售趋势会补齐范围内无数据的日期，便于管理端直接绘制连续折线图。商品排行按支付成功订单的商品销量排序，退款订单数作为独立指标返回。库存分析支持SKU编码、SKU名称、商品名称搜索和低库存筛选；库存变动区分入库、出库、销售扣减、售后退回、盘点调整。CSV使用UTF-8 BOM，包含订单金额、优惠、退款、收货人及运单信息。
