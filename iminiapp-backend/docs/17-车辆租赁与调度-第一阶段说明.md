# 车辆租赁与调度：第一阶段（内部用车）

## 已完成范围

第一阶段只处理内部用车，不产生支付和押金：

`PENDING_APPROVAL`（员工提交）→ `APPROVED`（管理员通过）→ `WAITING_DRIVER`（派车）→ `ACCEPTED`（司机接单）→ `IN_SERVICE`（出车）→ `COMPLETED`（行程完成）。

管理员也可以审核拒绝，状态为 `REJECTED`。每次状态变化都会写入订单状态轨迹、派车/行程日志和审计日志。

## 本阶段接口

| 端 | 接口 | 用途 |
| --- | --- | --- |
| 用户端 | `POST /api/v1/app/vehicle-applications` | 提交内部用车申请；必须传入新的 `Idempotency-Key` |
| 用户端 | `GET /api/v1/app/vehicle-applications` | 查询本人申请 |
| 管理端 | `GET /api/v1/admin/vehicle-applications` | 按状态查询申请 |
| 管理端 | `POST /api/v1/admin/vehicle-applications/{id}/review` | 审批通过或拒绝 |
| 管理端 | `GET /api/v1/admin/vehicles` | 查询车辆及状态 |
| 管理端 | `GET /api/v1/admin/vehicle-drivers` | 查询司机编号和状态，不泄露敏感信息 |
| 管理端 | `POST /api/v1/admin/vehicle-applications/{id}/dispatch` | 派车，并校验时段、座位数、车辆和司机状态 |
| 管理端 | `POST /api/v1/admin/vehicle-dispatches/{id}/accept` | 记录司机接单（第一阶段由管理端代操作） |
| 管理端 | `POST /api/v1/admin/vehicle-dispatches/{id}/depart` | 记录车辆出发 |
| 管理端 | `POST /api/v1/admin/vehicle-dispatches/{id}/complete` | 完成行程，回写车辆里程、油耗，恢复车辆和司机可用 |

## 演示数据

迁移 `V18` 会创建内部用车服务 SKU、三辆演示车辆（小轿车、GL8、考斯特）和两名演示司机。司机接口仅返回编号与工作状态。

## 本阶段边界

尚未实现社会租赁报价、押金和支付；也尚未提供独立司机账号/司机端。它们属于第二阶段，避免在内部用车流程稳定前接入真实微信支付。
