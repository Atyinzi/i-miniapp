# 住宿预订模块第二阶段说明

## 完成范围

第二阶段在第一阶段房型、价格和日库存基础上完成住宿报价、在线预订、订单查询、取消、待支付改订、支付退款衔接及低库存/售罄风险预警。

住宿订单按入住日至退房日前一天拆分为逐晚订单明细。统一订单服务在同一事务中逐日锁定库存，任意一天库存不足都会回滚整个订单，避免部分日期成功和超售。

## 业务规则

- 单次住宿支持1至20晚、1至99间房。
- 报价返回每天单价、可用库存、预计总额和低库存提示。
- 联系人和入住人姓名、手机号、证件号码加密保存，证件号码对用户端脱敏展示。
- 创建订单必须提供唯一 `Idempotency-Key`，重复请求返回原订单。
- 待支付订单有效期沿用统一订单的15分钟配置，超时后自动取消并释放所有逐晚库存。
- 待支付订单可以原子改订：原订单释放库存，新订单锁定库存；新预订失败时原取消操作整体回滚。
- 已支付订单不能直接改订，应先申请退款后重新预订。
- 住宿退款仅允许入住日前、已支付且未使用的订单；审核退款成功后逐晚归还库存。
- 支付沿用统一 `PaymentGateway`。本地环境提供 `mock-pay`，生产环境替换网关实现后住宿接口无需调整。
- 下单后剩余库存达到预警阈值时产生 `LOW_STOCK`；库存售罄时产生 `SOLD_OUT_RISK`。

## 用户端接口

- `POST /api/v1/app/hotel/quote`：住宿报价。
- `POST /api/v1/app/hotel/bookings`：创建住宿订单。
- `GET /api/v1/app/hotel/bookings`：我的住宿订单。
- `GET /api/v1/app/hotel/bookings/{reservationId}`：住宿订单详情。
- `POST /api/v1/app/hotel/bookings/{reservationId}/cancel`：取消待支付订单。
- `PUT /api/v1/app/hotel/bookings/{reservationId}`：修改待支付订单。
- `POST /api/v1/app/hotel/bookings/{reservationId}/refund-applications`：申请退款。
- `POST /api/v1/app/orders/{orderId}/mock-pay`：本地模拟支付。

## 管理端接口

- `GET /api/v1/admin/hotels/inventory-alerts`：查询住宿库存预警。
- `POST /api/v1/admin/hotels/inventory-alerts/{alertId}/resolve`：人工关闭预警。

系统每分钟自动检查已恢复库存的日期并关闭对应预警。完整联调请求见 `http/hotel-stage2-api.http`。
