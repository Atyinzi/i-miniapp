# i某小程序 - 测试与验收执行手册

版本：v1.0（2026-08-03）
范围：当前已实现的后端公共底座与景区门票预订能力。

## 1. 验收环境与证据

| 项目 | 要求 |
| --- | --- |
| 后端 | JDK 17，启动 `IminiappBackendApplication` |
| 数据库 | MySQL 8，数据库名 `iminiapp`，Flyway 最新版本为 V16 |
| 缓存 | Redis 7，默认 `localhost:6379` |
| 接口工具 | IDEA HTTP Client，使用 `http/api-examples.http` |
| 自动化测试 | Maven 单元测试与集成测试 |
| 证据 | 请求/响应截图、`traceId`、测试报告、测试日期、执行人和缺陷编号 |

验收前禁止使用生产数据、真实身份证号、真实支付密钥或真实微信商户证书。开发演示数据仅用于功能验证。

## 2. 功能验收用例

| 编号 | 场景 | 执行步骤 | 预期结果 |
| --- | --- | --- | --- |
| AT-01 | 权限隔离 | 分别以 USER、ADMIN、OPS 调用对方端接口 | 跨端返回 403；无令牌返回 401 |
| AT-02 | 景区票务查询 | 登录后查询景区、详情和指定日期票种 | 返回上架数据、价格、库存、规则；日期格式正确 |
| AT-03 | 创建订单幂等 | 对同一请求连续提交相同 `Idempotency-Key` | 仅创建一笔订单，库存只扣减一次 |
| AT-04 | 模拟支付与电子票 | 支付待付款景区订单后查询电子票 | 订单为 PAID，按购买数量生成 UNUSED 电子票 |
| AT-05 | 二维码/身份证核销 | 管理员核销电子票或当天实名票 | 首次成功；重复核销返回 409；全部票用完后订单完成 |
| AT-06 | 项目套票 | 配置两个组件、设置套票库存、下单并支付 | 返回组件电子票；各组件可独立核销 |
| AT-07 | 退款审核成功 | 用户申请→管理员通过→模拟回调成功 | 状态依次为 PENDING_REVIEW、PROCESSING、SUCCESS；订单 REFUNDED、票 VOID、库存归还一次 |
| AT-08 | 退款拒绝/失败 | 管理员拒绝或回调 FAILED | 订单恢复/保持已支付，库存和电子票不被错误改变 |
| AT-09 | 导览发布控制 | 创建 ACTIVE 与 INACTIVE 导览，用户端查询 | 用户仅看到 ACTIVE；管理员可看到全部内容 |
| AT-10 | 运营与审计 | 核销后查询运营概览、核销记录、订单时间线 | 数据按日期口径聚合，退款流程与核销记录可追溯 |

执行顺序以 `http/api-examples.http` 为准。退款回调为开发模拟接口，需携带本地回调密钥；正式环境必须替换为微信支付 V3 回调验签。

## 3. 自动化测试准入

提交前至少执行：

```powershell
mvn test
mvn failsafe:integration-test failsafe:verify -Pintegration-test -Dit.test=ScenicPackageIT,ScenicGuideIT,RefundWorkflowIT
```

通过标准：所有测试为 0 failures、0 errors。若 Redis 集成测试无法连接 Redis，应修复 Redis 服务后重跑，不能把“跳过”写成通过。

## 4. 非功能测试计划

| 类型 | 目标 | 验收证据 |
| --- | --- | --- |
| 性能 | 单接口 ≤500ms、复杂查询 ≤1s；以真实数据量复测 | k6/JMeter 脚本、P95/P99、并发数、应用/MySQL/Redis指标 |
| 并发 | 同一库存、同一退款、同一电子票不能重复处理 | 并发脚本、订单/库存/状态流水核对结果 |
| 安全 | 鉴权、越权、令牌失效、脱敏、限流、回调验签 | 安全检查清单、扫描报告、整改记录 |
| 恢复 | 数据库备份可恢复，迁移可在空库和升级库执行 | 备份文件、恢复演练记录、Flyway 迁移日志 |

这些项目在真实部署环境执行前只能标注“待执行”，不得填写虚构的性能、安全或生产验收结论。
