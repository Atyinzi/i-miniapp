# 自动化测试使用说明

## 测试分层

- 单元测试：不连接数据库，用于验证权限、订单状态、加密和适配器规则。
- 数据库集成测试：连接独立的 `iminiapp_test` 数据库，验证真实 SQL、Flyway 和业务事务。

测试数据库与开发数据库 `iminiapp` 完全分开。集成测试中的订单、库存和票务数据会在每个测试结束后回滚。

## 在 IDEA 运行单元测试

1. 打开 Maven 工具窗口。
2. 展开 `Lifecycle`。
3. 双击 `test`。
4. 控制台出现 `BUILD SUCCESS`，并且失败数为 `0`，表示通过。

## 在 IDEA 运行数据库集成测试

1. 确认 MySQL 已启动。
2. 确认项目根目录存在不入库的 `application-local.properties`，并填写本机数据库密码。
3. 打开 `OrderLifecycleIT.java`。
4. 点击测试类左侧绿色运行按钮，选择“运行 OrderLifecycleIT”。
5. 两个测试均显示绿色，表示订单闭环通过。

IDEA 运行配置的 Working directory 应为后端项目根目录，否则无法自动加载本地密码文件。

## 使用 Maven 运行

只运行单元测试：

```powershell
.\mvnw.cmd test
```

运行单元测试和数据库集成测试：

```powershell
.\mvnw.cmd clean verify -Pintegration-test
```

## 当前覆盖的数据库闭环

1. 创建订单并扣减库存。
2. 模拟支付并签发电子票。
3. 未核销订单退款、电子票作废、库存恢复。
4. 支付后核销电子票，订单自动变为 `COMPLETED`。
5. 在全新测试库中执行 V1 至 V8 的全部 Flyway 迁移。

## 注意事项

- 不要把真实数据库密码写入 `src/main/resources/application.properties`。
- 不要提交 `application-local.properties`。
- 集成测试固定使用 `iminiapp_test`，不要改成开发库或生产库。
- 如果构建提示 JAR 正被占用，先停止通过该 JAR 启动的旧后端进程，再运行 `clean verify`。
