# 模块开发接入说明

## 分工边界

公共底座统一维护 `identity`、`catalog`、`order`、`payment`、`refund`、`verification` 和 `shared`。
具体模块开发人员在独立包中开发，例如 `scenic`、`hotel`、`dining`、`meeting`。不得重复实现订单、支付、退款、库存和核销。

## 数据关联

| 业务扩展对象 | 公共关联字段 |
| --- | --- |
| 资源业务资料 | `bf_resource.id` |
| SKU 业务规则 | `bf_resource_sku.id` |
| 日期/时段库存 | `bf_inventory.id` |
| 订单业务扩展 | `bf_order.id` |
| 游客、入住人等明细 | `bf_order_item.id` |
| 电子票 | `bf_verification.order_item_id` |

新增数据库结构必须创建新的 Flyway 迁移，禁止修改已经提交和执行的 `V1`～`V8`。

## 订单业务扩展接入

具体模块通过实现 `OrderBusinessExtension` 接入统一订单，不得直接修改订单核心流程：

1. `resourceType()` 返回模块负责的资源类型。
2. `validate()` 在扣减库存和创建订单前校验模块业务数据。
3. `save()` 在同一个数据库事务中保存扩展表数据；失败会回滚订单和库存。
4. 模块专属请求数据放在订单明细的 `businessData` 中。

景区门票模块已经提供参考实现 `ScenicTicketOrderExtension`。住宿、会议和餐饮模块应复制这种接入方式，但使用各自独立的扩展表，不能复制订单、支付和库存表。

实名姓名、手机号和证件号码使用 AES-GCM 加密保存，证件检索使用带密钥摘要。正式环境必须通过 `PERSON_DATA_KEY` 提供独立随机密钥，禁止使用默认开发密钥，也不得在代码仓库中提交密钥。

## 本地启动

1. 安装 JDK 17、MySQL 8 和 Redis 7。
2. 创建数据库 `iminiapp`。
3. 将 `config/application-env.example` 中的配置复制到 IDEA 运行配置并填写本地密码。
4. 运行 `IminiappBackendApplication`，Flyway 会自动迁移数据库。
5. 使用 `http/api-examples.http` 完成登录、资源、订单、支付和电子票联调。

## Git 协作

模块开发人员从集成分支创建 `feature/<module-name>`，只提交源代码、迁移、测试和文档。
禁止提交 `.idea`、`target`、本地密码、访问令牌和 `http/local-api.http`。
