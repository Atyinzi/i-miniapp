# 住宿预订模块第一阶段说明

## 交付范围

第一阶段完成酒店门店、房型、实体房间、设施、图片、价格规则和逐日库存管理，并提供小程序端酒店展示及按入住日期查询可订房型的接口。在线下单、支付、改订、退款、入住核销和退房结算属于后续阶段。

房型创建时同步建立统一资源 `HOTEL_ROOM`、SKU 和逐日 `bf_inventory` 库存，后续住宿订单直接使用房型返回的 `skuId` 锁定多晚库存。

## 价格规则

- 支持 `HOLIDAY`、`PEAK_SEASON`、`LOW_SEASON`、`WEEKEND`、`MANUAL`。
- 所有规则保存最终每晚价格，单位为分。
- 日期和星期同时配置时必须同时命中。
- 同一天命中多个规则时使用优先级最高的规则；优先级相同则使用后创建的规则。
- 未命中规则时使用房型基础价。
- 生成库存日历后修改价格规则不会静默改变既有订单价格，需要重新执行日历生成接口刷新尚未销售日期。

## 库存规则

- 房型总库存不能超过房型维护的总房量。
- 日历重新生成时保留已经锁定或售出的房量，只更新剩余可售量和价格。
- 管理员人工调整库存时不能减少已经锁定或售出的房量。
- 可用库存小于等于房型预警阈值时，日历接口返回 `lowStock=true`。
- 可订查询要求入住至退房前的每一天都有库存且均满足请求房间数。

## 主要接口

- `GET/POST/PUT /api/v1/admin/hotels`：酒店维护。
- `GET/POST/PUT /api/v1/admin/hotels/room-types`：房型、设施、图片维护。
- `GET/POST/PUT /api/v1/admin/hotels/rooms`：实体房间及房态维护。
- `GET/POST/PUT /api/v1/admin/hotels/price-rules`：节假日及淡旺季价格规则。
- `POST /api/v1/admin/hotels/inventory/calendar/generate`：批量生成价格库存日历。
- `GET/PUT /api/v1/admin/hotels/room-types/{roomTypeId}/inventory`：查询或人工调整日库存。
- `GET /api/v1/app/hotels`：用户端酒店列表。
- `GET /api/v1/app/hotels/{hotelId}`：酒店及房型详情。
- `GET /api/v1/app/hotels/{hotelId}/room-types`：按入住、退房日期和房间数查询可订房型。

完整请求样例见 `http/hotel-stage1-api.http`。
