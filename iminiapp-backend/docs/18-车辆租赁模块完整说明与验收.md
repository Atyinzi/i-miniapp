# 车辆租赁与调度模块完整说明与验收

## 1. 实现范围

本模块同时支持内部审批用车和社会租赁用车。按照当前项目决定，内部用车采用单级审核，多级审批暂不实现。

### 1.1 内部审批用车

- 用户提交用车事由、起止时间、出发地、目的地、人数和预计里程。
- 管理员查询并通过或拒绝申请。
- 管理员选择满足座位数且时间不冲突的车辆和可用司机派单。
- 支持司机接单、出车、位置上报、行程日志和完成行程。
- 完成后记录实际里程、油耗，自动释放车辆和司机。
- 统计申请数、通过数、拒绝数、派车数、完成数、里程和油耗。

### 1.2 社会租赁用车

- 管理员维护车型、座位数、能源类型、车辆图片、配置、状态和里程。
- 管理员维护半日、全日、包月、裸租包月、超时和超公里价格。
- 新车型配置价格后自动生成可售资源和 SKU，用户端可以立即查询和报价。
- 管理员维护司机；姓名、手机号和驾驶证号加密保存，查询时脱敏。
- 管理员可设置车辆维修、保养、年检等不可租时段。
- 用户查询车型和实体车辆，按时段、人数、预计里程获取报价和可用车辆数。
- 用户创建订单并模拟支付；租金和押金分别记账。
- 管理员派车、司机接单、车辆出发、位置上报、轨迹查询和还车验收。
- 还车时按向上取整小时计算超时费，并计算超公里费。
- 额外费用先从押金抵扣；剩余押金退款；押金不足时生成待补款结算单。
- 用户查询结算结果，并可模拟补款完成订单。
- 正式退款和模拟退款均会同步处理车辆押金账本，不对车辆订单执行门票库存恢复。
- 管理员查询社会租赁订单，并查看、导出 CSV、打印运营报表。

## 2. 关键状态流程

社会租赁主流程：

`PENDING_PAYMENT` → `PAID` → `WAITING_DRIVER` → `ACCEPTED` → `IN_SERVICE` → `COMPLETED`

还车结算流程：

- 押金足够：`SETTLED`，押金分为已抵扣和已退款两部分。
- 押金不足：`PENDING_SUPPLEMENT`，补款后变为 `SETTLED`，订单变为 `COMPLETED`。

车辆和司机在派车后变为占用状态，在还车结算后恢复可用。派车会校验车辆车型、座位数、司机状态、订单时段冲突和不可租时段。

## 3. 数据库内容

车辆模块使用以下主要表：

| 表 | 作用 |
| --- | --- |
| `bf_vehicle_model` | 车型档案 |
| `bf_vehicle_tariff` | 车型价格和超额计费规则 |
| `bf_vehicle` | 实体车辆、图片、配置、状态和里程 |
| `bf_driver` | 司机档案及加密敏感信息 |
| `bf_vehicle_booking` | 内部用车或社会租赁的预订业务数据 |
| `bf_vehicle_dispatch` | 车辆、司机和派单状态 |
| `bf_vehicle_trip_log` | 接单、出发、位置、完成等行程日志 |
| `bf_vehicle_handover` | 交车和还车验收信息、图片 |
| `bf_vehicle_deposit` | 押金收取、抵扣、退款和补款账本 |
| `bf_vehicle_settlement` | 超时、超公里、押金抵扣及补款结算单 |
| `bf_vehicle_unavailable_period` | 维修、保养、年检等不可租时段 |

数据库结构由 Flyway 的 `V18` 至 `V21` 迁移自动创建和升级。已经执行过的迁移文件不要修改，后续结构变化应新增 `V22` 及更高版本。

## 4. IDEA 验收方法

1. 启动 MySQL、Redis 和 `IminiappBackendApplication`。
2. 打开 `http/api-examples.http`，先依次执行第 1、2、3 步，获得用户和管理员令牌。
3. 执行第 55 至 64 步，验收内部用车完整流程。
4. 执行第 65 至 78 步，验收社会租赁的报价、下单、支付、派车、轨迹、还车和结算。
5. 第 77 步若返回 `PENDING_SUPPLEMENT`，再执行第 79 步；若返回 `SETTLED`，不需要补款。
6. 执行第 80 至 83 步，验收订单管理、统计、CSV 导出和打印。
7. 执行第 84 至 91 步，验收车型、价格、车辆、司机和不可租时段维护。

每次后端重启后需要重新执行登录请求。新建订单、车型、车辆和司机时应使用新的幂等键或唯一编号。

## 5. 外部系统接入边界

当前本地流程已可独立运行和验收，但以下功能需要甲方或第三方提供正式账号、密钥和协议后替换适配器：

- 微信支付、支付回调、退款和押金原路退回。
- GPS 或车载终端厂商的位置推送协议。
- 短信通知服务。
- 独立司机端或企业微信消息通知。

这些外部依赖不影响前端、管理端和其他后端模块按现有 REST API 开始联调。接入正式服务时保留现有业务状态机，只替换模拟支付、模拟退款和人工位置上报入口。

## 6. 当前明确不包含

- 多级审批：已按项目决定跳过，目前为单级管理员审核。
- 真实微信公众号或微信小程序支付环境：需要商户号、证书、AppID 和回调域名。
- 真实 GPS 硬件轨迹：需要设备厂商协议和鉴权信息。
