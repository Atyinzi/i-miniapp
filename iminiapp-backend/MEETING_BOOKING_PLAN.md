# 会议预订模块开发计划

## 阶段 1：基础资料（已完成）

- 会议室、固定设备、每周可预订时段、按日期/星期/时段/参会规模收费规则及配套服务数据模型。
- 管理端 CRUD/列表接口、输入与归属校验、开放时段和价格规则重叠保护、审计日志。
- 集成测试覆盖完整维护链路与关键冲突场景。

验收结果：`MeetingManagementIT` 3 项测试全部通过（0 failures / 0 errors）；后端 Maven 编译通过。

## 阶段 2：可订日历与报价（已完成）

- 按会议室、日期、人数和期望起止时间生成可订时段并计算最终报价。
- 校验会议室状态、容量、营业时间、每周开放规则与时段边界，输出结构化不可订原因。
- 收费规则按优先级、规则具体度和记录 ID 确定性匹配；无匹配价格时禁止进入下一阶段下单。
- 报价返回收费规则 ID、编码、名称、优先级和场地金额，供预订阶段服务端复核并保存价格快照。

验收结果：`MeetingAvailabilityIT` 覆盖正常报价、容量不足、非开放日期/时段、价格优先级、边界对齐及无价格规则场景。

## 阶段 3：预订申请与配套服务组合（已完成）

- 支持外部/内部会议草稿创建、列表、详情、提交和取消，创建接口具备用户级幂等保护。
- 支持设备租赁、茶歇、住宿服务组合，草稿保存费用快照，提交时服务端重新校验可订性并重新报价。
- 提交后创建 `MEETING_BOOKING` 统一订单及订单明细快照：外部会议进入待支付，内部会议进入待审批。
- 通用订单取消、支付超时和模拟支付均可识别会议订单并同步会议申请状态。
- 本阶段仅建立申请与订单，不锁定会议室；并发占用和释放由阶段 4 完成。

验收结果：`MeetingBookingIT` 覆盖外部/内部申请、组合服务、服务端复价、创建/提交/取消幂等、统一订单取消、不可订校验和数据归属隔离。

## 阶段 4：防超订与场次占用（已完成）

- 使用“会议室 + 日期”数据库行锁串行化提交检查，首次创建日期锁时先锁会议室主记录，避免唯一键并发死锁。
- 提交时以严格区间重叠规则检查所有有效占用状态；相邻边界时段互不冲突，同一/交叉时段仅允许一个申请成功。
- 待支付、待审批、已支付及后续有效履约状态占用会议室；取消和支付超时记录释放时间并立即恢复可订。
- 可订日历和指定时段报价实时读取占用，返回结构化原因 `TIME_SLOT_OCCUPIED`。

验收结果：顺序占用/释放、超时释放和双线程并发抢占测试通过，并确认并发相同时段仅一个提交成功。

## 阶段 5：内部多级审批（已完成）

- 管理端可配置1—20级审批流程，流程按版本保存；规则调整只影响新申请，不改变在途审批任务快照。
- 内部会议提交时自动创建统一审批实例和全部节点任务，首节点待审批，后续节点依次激活。
- 支持审批人待办、进度与完整轨迹查询、逐级通过、任一节点驳回、申请人撤回和重复操作幂等。
- 仅当前节点指定审批人可处理任务；配置、查看、审批和申请人数据均进行账号与归属校验。
- 终审通过同步会议申请和统一订单为已审批；驳回或撤回同步订单并立即释放会议室占用。

验收结果：两级顺序审批、流程版本快照、终审同步、越权拦截、驳回释放、申请人撤回及重复审批测试通过。

## 阶段 6：履约核销与使用记录（已完成）

- 外部会议支付后、内部会议终审通过后自动签发电子核销码，支持后台扫码核销入场。
- 核销后同步会议申请为使用中并写入会议使用记录；支持结束使用、误核销撤销和撤销后再次核销。
- 核销票行锁、状态条件更新和分次幂等流水共同防止重复核销；完整记录操作人、渠道、设备、状态变化及备注。

验收结果：`MeetingFulfillmentIT` 覆盖外部会议核销、重复拦截、撤销、再次核销、结束使用，以及内部会议终审自动签票。

## 阶段 7：Web 管理端、运营报表与联调验收（已完成）

- 后端提供全量预订台账查询、经营总览、会议室可用/占用分钟及利用率、配套服务销售排行和 UTF-8 CSV 导出。
- Web 管理端提供会议室、设备、开放时段、收费规则、配套服务维护，以及预订台账、多级审批、扫码核销、撤销/结束使用和运营报表页面。
- 管理端路由与侧边栏已接入“会议场地运营”，支持按日期、会议室、状态、类型和关键词筛选。

验收结果：`MeetingOperationIT` 覆盖台账、金额、利用率、配套服务统计及 CSV 导出；管理端生产构建通过。微信支付和小程序用户端按既定计划后续接入。
