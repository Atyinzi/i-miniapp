# API 契约与变更流程

1. `docs/openapi.yaml` 保留导入界面的旧 Mock 契约；真实 `/api/v1/**` 契约以后端 Controller、请求/响应模型和后端自动化测试为准。不得再把旧 `/api/**` 路径当作已上线接口。
2. 新接口或兼容性字段调整，先修改 OpenAPI，再同步前端服务层、后端实现和 Mock。
3. 删除字段、修改字段类型、修改枚举语义或改变路径均属于破坏性变更，必须新增 `/api/v2`，不得覆盖 `/api` 现有行为。
4. 合并前运行 `ruby scripts/verify-contract.rb`、全部 Node 测试和后端 `mvnw.cmd test`，同时验证旧 Mock 契约与真实后端契约。
5. 订单、退款、取消、支付及核销等写操作必须携带 `clientRequestId`；服务端以该字段或业务唯一键实现原子幂等，并记录审计信息。
6. 开发、体验和正式版分别使用 development、test、production 配置。第三方密钥及签名只能保存在后端。
7. 发布前冻结契约版本并保留上一版本部署包；发生不兼容问题时按上一版本契约回滚。
